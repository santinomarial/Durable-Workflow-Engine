# API and roles reference

Full OpenAPI documentation, generated from the running service, is at `/docs`.
This page covers what isn't self-evident from that schema: roles, audit
fields, and which endpoints are public.

## Roles

| Role | Permissions |
| --- | --- |
| `viewer` | Inspect executions, history, and fleet statistics |
| `operator` | Viewer permissions plus start, signal, update, cancellation, visibility editing, pause/resume, and dead-letter inspection |
| `admin` | Operator permissions plus termination, retry-as-new, metrics, and API audit access |

## Public endpoints

These require no bearer key:

- `/api/health`, `/api/health/live`, `/api/health/ready`
- the static console shell
- OpenAPI documentation (`/docs`)

Every other endpoint — all workflow data and every control endpoint —
requires a valid key sent as `Authorization: Bearer TOKEN`.

| Observability | `/metrics` (admin only, Prometheus) |

## Request protection

- `DWE_MAX_REQUEST_BYTES` bounds both fixed-length and streamed request
  bodies (default 1 MiB).
- `DWE_RATE_LIMIT_PER_MINUTE` limits requests per authenticated key, per API
  process (default 300). Enforce a shared limit at the ingress when running
  more than one API replica.
- Request IDs are generated by the server and returned on all normal API
  responses, for log and audit correlation.
- TLS termination belongs at a trusted ingress; the application does not
  terminate TLS itself.

## Audit record fields

Every successful or duplicate control-plane mutation appends an immutable
audit record, in the same PostgreSQL transaction as the workflow transition:

- server request ID
- actor key ID
- role
- action
- workflow ID
- acceptance result
- non-payload metadata

Signal and workflow payloads are excluded from audit records to avoid
duplicating sensitive business data.

## Console session handling

The console asks for a bearer token and keeps it only in tab-scoped
`sessionStorage`. It sends the token in the `Authorization: Bearer` header,
so browsers do not attach it implicitly and CSRF does not apply.
